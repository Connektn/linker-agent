1. Shared Secret Management
- The HMAC signature secret should be a separate signature secret.
- It's essential that the user always has an option to regenerate the secret.
- At present the user (tenant) operates in the cloud. So the secret should be created during onboarding and then passed to the agent. We will tackle this in the cloud part of this story.
- In the future, if the secret changes locally the agent must report this to the cloud. No action needed for now.

2. Stop/Restart Commands
- Use whichever approach makes sense. I simply want a reliable way to stop / start the k8s cluster running the agent and its gateway.

3. Agent ID
- The ID is generated on the first run.

To give you the full picture - here's how a tenant starts the agent during onboarding:

-----
```
# Replace with your actual org code
export ORG_CODE="org_abc123xyz"

docker run --rm \
  --add-host=host.docker.internal:host-gateway \
  -e ORG_CODE=$ORG_CODE \
  -e REGION=eu-west-1 \
  connektn/linker-agent:latest
Expected Output:

INFO - ✓ Registration successful
INFO -   Agent ID: agent_...
INFO -   Organization ID: org_...
WARNING - Agent registered successfully!
WARNING - To send heartbeats, you need to provide your API key:
...

Dashboard Check: Refresh dashboard - agent status should still be 🟡 "Waiting"
------

This is obsolete, since we switched to k8s, but you get the picture.
